# Tarka 1.3.0-beta — release notes (honest)

**Status:** pre-release / beta on `master` (not a finalized GA tag yet)  
**Compared to:** published **v1.1.0**  
**Authority:** [`STUB_REGISTER.md`](https://github.com/pamu512/tarka/blob/master/docs/STUB_REGISTER.md) · [feature data flows](https://github.com/pamu512/tarka/blob/master/docs/docs/guides/feature-data-flows.md) · [productionization](https://github.com/pamu512/tarka/blob/master/docs/docs/guides/repo-productionization-runbook.md)

These notes describe **what landed in code** since v1.1.0. They replace the obsolete June 2026 “Trust Center / signed artifacts” draft, which never matched the shipped train.

---

## Theme

**Local-first fraud OS with fail-closed honesty:** Rust JSON packs decide; graph + depth fuse context; Shadow / investigation / trend **advise only**; day-1 desk is compose-lite + fraud-desk.

---

## Highlights (shipped)

### Evaluate & core plane

- **`core-api` macroservice** — decision-api + case-api in one day-1 process (lite / fraud-desk compose).
- **Authoritative evaluate** via **`tarka_rule_engine`** (Rust JSON packs). Visual Rego/OPA **transpile deleted**; legacy `POST /v1/rules/rego/compile` is **410 Gone**.
- Python rule_engine HTTP evaluate is **legacy / dual-run only**; demo ruleset requires `RULE_ENGINE_ALLOW_DEMO_FALLBACK=1`.

### Honesty / invent-success fail-closed

Tier-1 Stub Register rows **SR-01 … SR-17** closed (Ship / Delete / Degrade). Notable contracts:

| Area | Behavior |
|------|----------|
| Feature store | Durable Postgres + ClickHouse DDL; no `_STORE` SoR |
| KPI dashboards | Live analytics or **503** (no null stub success) |
| Backtest | Jobs path only; stub `/run` removed |
| NL→SQL | **503** when LLM offline (no fake SQL success) |
| Desk mocks | Forbidden in prod builds; desk-strict includes trend ops (SR-13) |
| Shadow modulation | Default `SHADOW_ACTION_MODULATION=escalate_only` — never silent FLAG→ALLOW |
| Bot / graph / mule / demo-burst | Refuse invent-success; opt-in demos only |

CI: `scripts/audit_stubs.py`, `scripts/audit_prod_desk_mocks.py`.

### AI ops (advise only)

- **Trend agent** — watch / tick / drafts / HIL / promote posture; `wasm_ready=false`; promote never auto-applies Wasm (`409 never_auto_promote`).
- Compose **`--profile trend-tick`** / `make trend-tick` / `scripts/trend_tick_loop.sh`.
- Ops UI: calibration + trend panel; AgentRun discovery.
- Shadow remains local-first (Ollama by default); ingest calls Shadow only on `SHADOW_REVIEW`.

### Depth, verticals, marketplace

- Depth / ring / lifecycle / partner fusion on the evaluate path.
- Marketplace / COD / loyalty / payout / dispute / promo–seller boards and bridges (label-gated promote, fail-soft where documented).
- Partner fusion + diligence gates stay **offline / WAIVED** without live credentials — no forged LIVE pins.

### Desk & deploy

- Recommended day-1: `docker-compose.lite.yml` + `docker-compose.fraud-desk.yml`.
- Ingest rail: `docker-compose.v2-ingest.yml`.
- Graph: Janus/Gremlin story with `GRAPH_BACKEND`; Neo4j still available on some paths.
- Docs hub cleaned to Tarka operator docs ([`docs/INDEX.md`](https://github.com/pamu512/tarka/blob/master/docs/INDEX.md)); competitive/scorecard fluff removed.

---

## Breaking / behavior changes (operators)

Expect these vs older “happy path” demos:

1. Surfaces that used to return stub success now **503 / 410 / 501** or empty honest payloads.
2. Shadow **does not** clear deterministic **FLAG** to **ALLOW** unless `SHADOW_ACTION_MODULATION=legacy` (explicit opt-in).
3. Production / desk-strict frontends **do not** auto-fall back to API mocks.
4. Rule-engine demo rules do nothing unless `RULE_ENGINE_ALLOW_DEMO_FALLBACK=1`.

## Not claimed in this beta

- SOC 2 / PCI certification or live named-tenant L3 ops.
- Native vendor network / Motiva-class screening as a closed product claim.
- Signed release artifact / Trust Center procurement pack as the primary ship theme (that was the old draft; not this train).
- Final GA **v1.3.0** tag — publish only after required CI (including **stack-smoke**) is green on the release commit.

## Upgrade from v1.1.0

1. Pull `master` (or the beta tag when cut).
2. Prefer **fraud-desk** compose for analyst UI; wire `DECISION_API_URL` / `RULE_EVAL_BACKEND=decision_api` on ingest.
3. Review env knobs in [repo-productionization-runbook](https://github.com/pamu512/tarka/blob/master/docs/docs/guides/repo-productionization-runbook.md) (`TREND_*`, `SHADOW_ACTION_MODULATION`, mock flags).
4. Re-read [`STUB_REGISTER.md`](https://github.com/pamu512/tarka/blob/master/docs/STUB_REGISTER.md) for degraded contracts you may have relied on as success.
